# Architecture

## Source layout

```text
main/
  main.c            start-up order, LVGL task
  board.c           LCD (MIPI-DSI, LVGL direct mode into two frame buffers,
                    flipped on vsync), touch, backlight, VCOM, flip, screen saver
  panel_jc8012_v2.h JD9365 init sequence for the V2 panel
  settings.c        NVS-backed settings, timezone table
  wifi.c            Wi-Fi station via the ESP32-C6, scan, SNTP
  adsb_client.c     TCP client, Beast / AVR / SBS parsers, reconnect logic
  modes.c           Mode S / ADS-B / Comm-B decoder, CPR
  aircraft.c        aircraft table, position decoding, trails, derived values
  icao_db.c         ICAO address block → country, military ranges (generated)
  lookup.c          adsbdb.com enrichment and photo download, with caches
  map_data_none.c   empty map (map_data.c is generated by tools/gen_map.py)
  ota.c             web upload, image checks, boot verification, rollback,
                    C6 update
  ui.c              LVGL user interface
  selftest.c        decoder reference vectors
components/
  esp_lcd_touch_gsl3680   GSL3680 touch driver (Guition, with fixes)
c6_coprocessor/           ESP-Hosted co-processor firmware project for the C6
tools/gen_map.py          offline map generator
```

## Tasks

| Task | Core | Role |
|---|---|---|
| `lvgl` | 0 | Renders the UI; a 1 s timer snapshots the aircraft table and refreshes everything |
| `feed` | 1 | Receives and parses the ADS-B stream, feeds the decoder |
| `lookup` | 1 | Online enrichment, photos |
| `httpd` | any | OTA upload page |
| ESP-Hosted / lwIP | — | Wi-Fi traffic to and from the C6 |

The aircraft table lives in PSRAM behind a mutex. The UI never draws while
holding it: it copies what it needs into a snapshot first.

## Display pipeline

The DPI panel driver owns two full-screen RGB565 frame buffers in PSRAM. LVGL
renders in **direct mode** straight into the off-screen buffer; on the last
area of a frame the flush callback hands that buffer to the DSI engine and
waits for the next vsync, so there is no copy and no tearing. LVGL keeps the
two buffers in sync.

## Flash layout

| Partition | Offset | Size | |
|---|---|---|---|
| nvs | 0xB000 | 24 KB | settings, Wi-Fi |
| otadata | 0x11000 | 8 KB | which slot boots |
| phy_init | 0x13000 | 4 KB | |
| ota_0 | 0x20000 | 6 MB | app slot A |
| ota_1 | 0x620000 | 6 MB | app slot B |
| storage | 0xC20000 | ~4 MB | spare |

The bootloader has app rollback enabled; see [Firmware updates](ota.md).

## Configuration

- `sdkconfig.defaults` — project defaults (committed)
- `sdkconfig.defaults.rev1` — overlay for ESP32-P4 rev < 3
- `sdkconfig.defaults.local` — your private defaults (git-ignored, picked up
  automatically); see `sdkconfig.defaults.local.example`
- `idf.py menuconfig` → **ADS-B Display** — defaults and board orientation

## Versioning

The firmware version is `PROJECT_VER` in the top-level `CMakeLists.txt`. Bump it
for every release so the OTA status page and Settings show which build runs.
